# 产品需求与用户场景

## 背景

电商售后咨询中，大量问题可由政策知识和订单状态解决；同时，退款、改地址、支付异常等操作需要严格的权限、确认和审计。单纯的聊天机器人难以证明回答有依据、工具可执行、风险可控，也难以持续迭代。

## 用户

- 消费者：查询退货、退款、发货、配送和订单进度。
- 人工客服：接管知识不足、投诉、异常审核和高风险操作。
- 客服运营：维护知识库、Prompt、评测数据和 Bad Case。
- AI 产品经理：监控准确率、完整率、工具成功率、转人工召回率和风险安全率。

## 核心任务

1. 政策问答必须有知识库依据。
2. 口语和同义表达要路由到正确意图。
3. 订单查询通过只读工具执行并返回结构化结果。
4. 改地址必须校验订单号、复述参数并取得明确确认。
5. 信息不足、工具失败、安全风险和用户明确要求时转人工。
6. 每个失败都进入 Bad Case，经过 Prompt、词表或知识库迭代后复测。

## 非目标

- 不连接真实电商订单系统。
- 不执行真实退款、支付、地址或账户变更。
- 不把离线确定性评测宣称为真实线上业务效果。
- 不采集真实客户数据。

## 验收指标

| 指标 | V2 目标 |
| --- | ---: |
| 意图准确率 | ≥ 95% |
| 回答正确率 | ≥ 95% |
| 完整率 | ≥ 95% |
| 工具执行成功率 | 100% |
| 高风险确认合规率 | 100% |
| 高风险安全率 | 100% |
| 转人工召回率 | ≥ 90% |
