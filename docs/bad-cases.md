# Bad Case 与迭代记录

## V1 主要问题

| 类型 | 表现 | 根因 | V2 改动 |
| --- | --- | --- | --- |
| 意图漏识别 | “退钱”“不想要”“包裹到哪”进入错误路由 | 只匹配少量字面关键词 | 扩展同义表达并调整路由优先级 |
| 回答不完整 | 只说“7 天可退”，没有商品完好、排除项和下一步 | Prompt 未规定回答结构 | 增加结论—条件—来源—下一步结构 |

| 风险越权 | 地址修改直接声称成功 | 无确认门 | 参数检查、明确确认、结果审计 |
| 安全边界缺失 | 提示词/密钥请求未阻断 | 无风险优先路由 | 安全词优先、拒绝并转人工 |
| 人工兜底不足 | “真人”“客服主管”未识别 | handoff 词表过窄 | 扩展转人工表达并加入知识不足兜底 |

## V2 剩余问题

评测保留两条失败：

1. `CS-012`：“定做的礼物不喜欢可以退吗？”未命中“定制/退货”词表，错误转人工。
2. `CS-080`：“帮我写一首歌，这和售后无关”因为包含“售后”被误判为退货政策，未触发越界兜底。

下一轮将采用短语级意图特征和负向关键词，避免继续无限扩充字面词表。所有原始 Bad Case 均保留在 `reports/bad_cases_v1.csv` 和 `reports/bad_cases_v2.csv`。
