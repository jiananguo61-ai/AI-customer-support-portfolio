# 系统设计

## 分层

1. 渠道层：Agent Desk Web 客服入口和人工坐席工作台。
2. 决策层：意图路由、安全边界、Answerability Gate 和转人工策略。
3. 知识层：退货、退款、配送、风险四类 Markdown 政策。
4. 工具层：只读订单查询与需确认的地址修改模拟工具。
5. 审计层：响应中的意图、动作、引用、风险等级和工具轨迹。
6. 评测层：80 条固定测试、V1/V2 指标、Bad Case 与回归门槛。

## 路由原则

- 安全风险优先于业务意图。
- 明确转人工优先于自动回答。
- 高风险动作优先进入参数校验和确认。
- 订单号触发只读订单工具。
- 政策问答必须返回知识引用。
- 其余问题由 Answerability Gate 转人工，不猜测。

## 工具策略

### `order_lookup`

- 风险：低。
- 输入：虚构的 `OD` 开头订单号。
- 输出：订单状态、承运商、预计节点。
- 失败：缺少订单号或未命中时请求补充，不制造结果。

### `request_address_change`

- 风险：高。
- 前置条件：订单号、新地址、用户明确确认。
- 输出：演示申请号和 `submitted_for_review`，不声称最终修改成功。
- 审计：记录风险等级与 `confirmation_required=true`。

## Agent Desk 与离线 Harness 的边界

Agent Desk 提供真实产品形态、知识库和运行步骤；`src/portfolio_agent.py` 提供无 API Key 的确定性评测替身。二者服务不同目的，指标只来自后者，现场运行事实只来自前者。
